Last.fm Discover metadata fix

Why the console showed many 429/403 iTunes errors:
- Last.fm was working correctly and returning 50 recommendations per request.
- Discover then tried to resolve dozens of those recommendations through iTunes immediately.
- That burst hit iTunes Search API throttling; the apparent CORS messages were on failed 429 responses.

What changed:
- Last.fm Artist and Song recommendations are now first-class Discover candidates.
- Artist/Song feeds do not require an iTunes request per card.
- Stable Last.fm-derived provider IDs are used for saving/deduping.
- iTunes metadata is resolved lazily when a specific Artist/Song detail is opened.
- If iTunes is temporarily unavailable, the Last.fm card remains usable/savable and the detail can link to Last.fm.
- Dedicated Artist/Song views skip familiar-material iTunes searches.
- Related-artist album enrichment in mixed For You was reduced from six per batch to two.

Expected console behavior:
- Many [Last.fm API] ... results lines.
- [Discover][Music] Last.fm artist candidates mapped directly ... iTunesRequests: 0
- [Discover][Music] Last.fm track candidates mapped directly ... iTunesRequests: 0
- No wall of iTunes 429 requests while simply loading Artist/Song Discover.
- One/few iTunes requests only after opening a specific Artist/Song detail.
