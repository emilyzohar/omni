LAST.FM CONFIG DIAGNOSTIC

The app now logs at startup:
[Config] API availability

Check these fields:
- lastFmConfigured: true
- lastFmEnvName: VITE_LASTFM_API_KEY (recommended) or EXPO_PUBLIC_LASTFM_API_KEY

If false, Last.fm requests cannot run at all. Set the env variable and RESTART/REBUILD the Vite app.

Recommended:
VITE_LASTFM_API_KEY=YOUR_KEY

The key value is never logged.

LAST.FM DISCOVER DEBUGGING

Environment variable:
EXPO_PUBLIC_LASTFM_API_KEY=YOUR_LASTFM_API_KEY

Open the browser developer console while using Discover > For You > Artist or Song.
The app now logs the recommendation pipeline without logging the API key.

Expected messages:

[Last.fm API] request
- Confirms a Last.fm endpoint is being called.
- Shows method and non-secret request parameters only.

[Last.fm API] artist.getSimilar results / track.getSimilar results
- Shows how many raw Last.fm recommendations came back.

[Discover][Music] artist iTunes resolution / track iTunes resolution
- supplied: usable Last.fm names available for resolution
- attempted: how many were tried against iTunes
- resolved: how many were successfully converted to tracker cards
- failed: unresolved/failed names
- target: number the app was trying to obtain

[Discover][Music] music collector complete
- Shows the deduplicated music candidate pool by type.

[Discover][Music] dedicated music view candidates
- Shows how many candidates match the currently selected Artist/Song/Album filter.

[Discover][Music] feed batch ranked
- Shows fresh candidate count and final rendered count.

Warnings:
[Discover][Music] Last.fm pool sparse; enabling iTunes supplemental fallback
- This is expected if Last.fm or iTunes resolution produces fewer than 24 Artist/Song candidates.
- The app then supplements Last.fm with broader iTunes catalogue searches instead of stopping at a tiny result set.

[Last.fm API] request failed / API error
- Indicates the API key, endpoint, network, or Last.fm itself returned an error.

The key itself is never written to the console.
